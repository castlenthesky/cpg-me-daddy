# @cpg/graph-visualizer

Status: partially implemented — owns the graph view layer (cosmos.gl render, legend, webview HTML shell). Knows `'file' | 'directory'` plus the CPG labels `@cpg/cpg-generator` produces (`METHOD` / `TYPE_DECL` / `IMPORT` / `CALL` / `LOCAL` / `SYMBOL`) today.

## API (`src/index.ts`)

- `GraphPayload` / `GraphNode` / `GraphEdge` (`contract.ts`) — the render data shape; `GraphNode.type` drives colour/legend grouping, `GraphNode.name` is the tooltip display name (never a full path — that's `id`). `GraphEdge.type` likewise drives the relationship legend/hover tooltip (see `relationshipTypes.ts`) but never a link's on-canvas colour — links always render as a gradient between their two endpoint nodes' colours (`linkColorInterpolateFromEndpoints`), never per edge type. `GraphEdge.data` is an open property bag like `GraphNode.data`; nothing in the renderer reads it for rendering (the link buffers are flat index pairs with no per-link colour/width slot tied to it), so it is a home for producer provenance (read back via `edgeResolution`), not a rendering channel.
- `edgeResolution(edge)` / `nodeResolution(node)` (`contract.ts`) — read back a cross-reference's `{ status, resolvedBy, confidence?, reason? }`. Mirrored onto the *node* as well as the edge because the interesting cases are the ones with **no** edge (a builtin, or something nothing could resolve) — edge-only provenance cannot describe an absent edge, and the tooltip appends it so an edge-less `CALL` explains itself.
- `GraphDelta` / `applyGraphDelta` (`contract.ts`) — incremental `{ addedNodes, addedEdges, removedNodeIds }`; removed edges are implicit (dropped when a touched node is removed).
- `SourceRange` / `NodeLocation` / `nodeLocation(node)` (`contract.ts`) — where a node's source lives, stored by producers under `GraphNode.data.location` and read back through `nodeLocation` (the one place that knows that key and shape). `range` is the construct's full extent, `nameRange` its identifier token. Rows are zero-based and columns are UTF-16 code units, so a range converts to `vscode.Position` with no arithmetic — see the type's doc comment for why that holds.
- `GraphVisualizer` (`visualizer.ts`) — mounts on an `HTMLDivElement`; `render(payload)` full-draws via cosmos.gl, `applyDelta(delta)` patches in place, `fitView()`/`dispose()` manage the camera/WebGL context. `options.onNodeClick` is the click seam — it fires with the clicked `GraphNode`, never for the synthetic multi-root anchor or a legend-hidden type, and is how a host acts on a click without this package knowing about VS Code. Renders two independently-hoverable, independently-toggleable legends stacked in `#legend-container`: a node-type legend (`#legend`) and a relationship (edge-type) legend (`#relationship-legend`), plus one shared tooltip element that hovering a point or a link both write into.
- `graphWebviewHtml(opts)` (`shell.ts`) — the webview HTML shell (CSP, sizing CSS, mount `<div>`).
- `layoutPayload(payload, hierarchyEdgeType?, fallbackParentEdgeTypes?)` (`layout.ts`) — pure layout math, exported for isolated testing. `DEFAULT_FALLBACK_PARENT_EDGE_TYPES` (`['DEFINES']`) is a **second** parent pass: a node with no hierarchy edge is placed under the source of a fallback-type edge instead of becoming a root. That exists for `SYMBOL` nodes, which by design have no `CONTAINS` parent — without it every symbol would be a root, forcing the synthetic-centre path and rendering a 20px grey dot with no tooltip at the middle of the graph. With it, a symbol sits beside the declaration that defines it, so a cross-file reference reads as a chord between two file clusters. Note that `layoutPayload`'s own `links`/`linkWidths` fields are unused by `GraphVisualizer` today (see Gotchas) — only `positions`/`colors`/`types`/`ids`/`sizes` feed the renderer.
- `NODE_TYPES` (`nodeTypes.ts`) — the colour/label registry; extend here when CPG node types beyond file/directory arrive.
- `RELATIONSHIP_TYPES` / `relationshipKey(type)` / `relationshipLabel(key)` / `relationshipColor(key)` (`relationshipTypes.ts`) — the edge-type equivalent, but deliberately not exhaustive like `NODE_TYPES`: `GraphEdge.type` is free-form, so the relationship legend derives its rows from whatever types are actually present in the payload, and this table only supplies a curated label/swatch for the ones it knows (`CONTAINS`/`DEFINES`/`CALLS`/`IMPORTS`) — anything else, including an edge with no `type` at all, falls back to the raw type string (or `'Untyped'`) and a neutral grey swatch under `relationshipKey`'s `UNTYPED_RELATIONSHIP_KEY` bucket.

## Gotchas

- The repo's only browser-targeted package: `"lib": ["ES2022", "DOM"]`, `"types": []`, still emits CommonJS.
- `contract.ts` and `shell.ts` must stay import-free — the CommonJS extension host deep-imports `dist/contract`/`dist/shell` instead of the ESM-only main entry.
- Multi-root layouts place a synthetic centre node with no real edge to the visible roots — not visually polished.
- `hiddenTypes` (node legend show/hide) and `hiddenEdgeTypes` (relationship legend show/hide) both persist per-instance across `render()` calls.
- `applyDelta`'s parent lookup must stay in step with `buildHierarchy` — hierarchy edge first, then a fallback-type edge. It once took the first edge of *any* type, which was harmless while every edge was `CONTAINS` but put the same node in two different places (full render vs. delta) as soon as other edge types existed.
- `links`/`linkWidths`/`linkEdges` are rebuilt from an authoritative `edgesByKey` map by `rebuildLinks`, not appended to — and, since the relationship-hover/toggle work, this is now the *only* place they're built: the full render path calls it too instead of trusting `layoutPayload`'s own link output, so a link index means the same thing (an offset into `linkEdges`) on the first render and after every later delta. Appending never shrank them, so each save used to re-append a file's whole fan: the link spring then applied n times and the subtree stiffened, and a stale link could resurrect against a recycled index — which with cross-file edges would draw a phantom "this file calls that one". Removal needs no `removedEdgeIds`: an edge dies exactly when an endpoint is removed, already `applyGraphDelta`'s rule.
- `visibleLinks`/`visibleLinkWidths`/`visibleLinkEdges` (built by `pushLinks`) are the *filtered* view of the above — hidden relationship types dropped — and are what's actually handed to cosmos.gl. A link index from `onLinkMouseOver`/`onLinkClick` is only ever meaningful against these, never against the authoritative `links`/`linkEdges`.
- `NODE_TYPES[].label` (a type's legend label) and `GraphNode.name` (a single node's display name) are unrelated despite similar names; same relationship between `RELATIONSHIP_TYPES[].label` and an edge's own type string.
- A link's hover tooltip has no position handed to it by cosmos.gl (unlike a point's), so `showLinkTooltip` re-derives one from the two endpoints' *live* positions (`graph.getPointPositions()`, not `basePositions`, which goes stale as soon as the simulation moves anything).
