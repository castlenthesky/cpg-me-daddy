# packages/engine: agent notes

Status (U2c.2). REAL: the walker and the filesystem tier, the `CpgEngine` port (`src/port.ts`, C-CLI Q1), `createEngine` (`connect` opens the sinks; `index` walks, then writes ONE merge-filesystem op through them; `verify` runs all six checks, `worstState`, and `--strict`; `schema` returns `CPG_SCHEMA`), `NullGraphStore` (backs `--dry-run`), and the config loader core (`resolveConfig`, `toCpgConfigInput`, `CONFIG_DEFAULTS`, `parseConfigFile`, `stringifyConfigFile`, `configFileLayer`, with per-switch consumer provenance). REAL (U2c.2): `createEngine` builds its sinks from the consumer switches; memory is always on; `falkor` is a SEAT that `connect` refuses before opening any sink (`inspect` is built since U2b.1 part 3b: the inspector is a front-door child process, not an engine sink; `vscode` is accepted since U3-prep: the panel lives in the VS Code host, so the engine builds nothing for it, controller decision 25); `verify` reads the built-in store and never host sinks. Within `verify`: `filesystem-reconciliation`, `id-uniqueness`, and `revision-reconciliation` are REAL against the built-in store; `identity-invariants` and `resolution-health` are SEAT and report `unavailable` until U6c (no code tier / ResolveReport yet); `render-reconciliation` reports `unavailable` inside `verify` (ND-8), and the front door that runs the renderer computes it with the pure `renderReconciliation` from the page's render-report and the node count it sent (U2b.1 part 3b, controller decisions 21 and 25: the report's own `payloadNodeCount` decides nothing); non-null `expected` (C-CLI Q9) is SEAT. Other SEATs: manifest discovery (the `manifest` config layer slot is reserved and empty), dialing a store target (FalkorStore, U5), `resolvers`/`processHost` (U6c/U8), `resumeFrom`, and the port's `read`/`doctor`. REAL (U4.2.1 part a, decisions 59-63): `watch` runs `index()`'s own code, then a `@cpg/watch` session seeded from the walk, with the engine's node:fs `WatchProbe` (`src/watch-probe.ts`) and the walker's one admission rule (`src/walker/admission.ts`, shared with `walkWorkspace`); each batch is one merge-filesystem op through every sink (`moves` stays `[]`: a move is a removal and an add), and the C-CLI `WatchEvent` stream reports it (`t0_t1` is null). `EngineDeps` takes `watchBackend` (default @parcel/watcher), `now` and `timers`. REAL (sprint 25, the drift crawl, decisions 76-80): `index` with a session removes what the memory store holds that the walk did not find (FILE and DIRECTORY paths, by label, never `'.'`), so a watch starts from the disk; `watch` crawls the tree again every `rescanIntervalMs` after each crawl ends (config `watch.rescanIntervalMs`, default 300000, 0 off; absent in the request: none) and on each command of `WatchRequest.rescan`, and each batch event carries its `cause`. REAL (sprint 26, decisions 81, 82): each batch event carries `deltas`, one GraphDelta per change built from the op it wrote (`toBatchDeltas`; `HeldPaths` is the engine's own record of the FILE and DIRECTORY paths it wrote, so a removed directory's delta names its subtree without a store read), and `graphSeq`, the watch's one graph seq (0 at ready, one more per delta). REAL (U2b.1 part 3b): `inspect` returns the built-in memory store whole (`MemoryStore.readAll`, C-CLI Q6); the session is unused until a store dials a target (U5). REAL (U3-prep): `filesystemReconciliation`, `idUniqueness`, `revisionReconciliation` and `unavailableCheck` are exported, so a host runs the same checks on its own payload and probe (decision 25).
REAL (U6a.3-2, controller decisions 98a, 100, 101): `index` runs the code tier (`src/code-tier.ts`): the walker hands each file's bytes to it (`WalkOptions.onFile`, one read), python files are decoded, parsed by one ParseService per engine (created on the first python file; `EngineConfig.grammarDir` is the locator's explicit rule) and extracted, and each tree is released before the next. After merge-filesystem come one replace-file per extracted file (walk order, `SOURCE_FILE` attached) and a delete-file per removed path the store held file-owned nodes for. Every seq comes from `MemoryStore.nextWriteSeq()`. A failure is a warning, never fatal. `IndexedFile.nodes/edges` are the code tier's counts.
REAL (U6a.3-3, controller decisions 102 and 110 reversed): `watch()` runs `index()`'s own code, code tier included, and each batch writes the code tier too: a `delete-file` per held code file at or under a deleted or moved-from path, the merge-filesystem op, then a `replace-file` per created, changed or moved-to python file, its bytes read once on the live change (`NodeWatchProbe.read`; nothing re-hashes, so a write that lands after the session's digest is healed by the batch it brings). `HeldCode` is the engine's own record of the file-owned ids it wrote per file (seeded by `IndexRun.heldCode` from the one store read `index()` makes), so each code write's `producer: 'code'` delta follows its change's own delta without a store read: the op's code nodes and SYMBOLs, its edges, and the ids held before (never a SYMBOL). A code delta carries no FILE row, so the FILE's code-owned half (`status`, `version`, `interface_hash`, `loc`) after a save is the store's alone (S34-1). A failure group (`failureWarnings`, shared with `index()`) is said once per watch, the index's included.
