# apps/inspector: agent notes

Status (U2b.1 part 3b and U3.1.1 part 3): REAL: `layoutPayload` (seeded radial seed layout), the node and relationship type registries, the headless renderer (`GraphVisualizer` over a `GraphSurface`, a `Pick` of cosmos.gl's `Graph`, including `drawn()`), and the page: `graphShellHtml` (strict CSP, connect source per owner decision 10a, `#cpg-verification` reserved), the themed component CSS (decision 11a), the DOM views (`mountGraphViews`), the cosmos.gl config (`graphConfig` with computed colours, decision 14), the C-EXT page protocol (`startGraphApp`, `parsePageMessage`), `renderReport`, the `#cpg-verification` banner (`verificationText`), the page's channel (`pageChannel`: VS Code's webview API when the page has it, else the WebSocket through `queuedChannel`; one bundle serves both, controller decision 31), the theme (a `theme` message's node colours, and the page's computed colours re-read; controller decision 32), the bundle (`bun run build:inspector`, `tools/build-inspector.mjs`), and the inspector process (owner decision 9a): the boundary parsers (`parseWebviewMessage`, `parseInspectorInput`), `InspectorHost`, the 127.0.0.1 server with its `ws` `WebviewTransport` (decision 8a; Host and Origin checked, controller decision 17), `runInspector` and the `cpg-inspector` bin (NDJSON on stdin; the listening line, then render-reports, on stdout; a stderr line at startup when the page bundle is missing). `cpg inspect` and `cpg index --inspect` (U2b.1 part 3b) start this bin as a child process; see `apps/cli/AGENTS.md`. The shell clips html, body and the graph container, and the canvas is a block, so the picture fits the window with no scrollbar.
Layout and rules: `docs/outline/03-architecture.md` §2. Root `AGENTS.md` applies.

- May import DOM/WebGL. Imports `@cpg/*` front doors only, no deep imports.
- `@cosmos.gl/graph` (exact pin, owner decision 7a) and `ws` (exact pin, owner decision 8a; only the server and the tests' page client) are this app's libraries. cosmos.gl is ESM-only and the app is CommonJS, so a type import needs `with { 'resolution-mode': 'import' }`. Only `src/graph-page.ts`, the bundle entry, imports it at runtime: `tsc -b` skips that file and `tsconfig.page.json` (DOM lib, bundler resolution, `@cpg/model` from source) typechecks it as part of `bun run typecheck`.
- `src/index.ts` is the package's front door, for hosts (controller decision 30): pure modules only, checked on the built module graph by `index.test.ts`. `tools/graph-page.test.mjs` runs the bundle's entry with a stand-in for cosmos.gl.
- The DOM views are typed against the structural `ViewElement<E>`/`ViewDocument<E>`, which the real DOM satisfies, so they compile without the DOM lib and the tests drive them with a fake document.
